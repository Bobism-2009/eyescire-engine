Installation

Eyescire currently supports Windows 10/11 (x64).

From the installer

  1. Download EyescireSetup (.7z)
  2. Extract and run EyescireSetup.exe

From source

You need clang++ and NexaC on your PATH.

git clone https://github.com/Bobism-2009/eyescire-engine.git
cd eyescire-engine
build.cmd
build\editor.exe

Or grab the source archive (.7z).

First steps

  1. Open the editor and create a New Project (Empty, Top-down, or 3D).
  2. Open a scene, place entities, attach a script from scripts/ if you want behavior.
  3. Press Play (Ctrl+P). Scripts compile to bin/*.dll and run in the same runtime the exporter ships.

A project is a folder with project.eye. Scenes live in scenes/, scripts in scripts/, and assets in assets/. That layout is what Play and Export both expect.

Projects

Everything you make lives in a project. The manifest project.eye names the game, lists scenes, and points at the start scene. 

project.eye
scenes/       # .scene files
scripts/      # .nxa game scripts (+ optional .ebp blueprints)
assets/       # images, .obj models, sounds
prefabs/      # reusable entity trees
bin/          # compiled script DLLs (generated)
dist/         # export output (generated)

Opening a project rescans these folders. You usually do not edit project.eye by hand — the editor keeps it in sync.

Scenes & entities

A scene is a tree of entities (transforms, kinds, components like sprites, lights, or scripts). Scenes are saved as text .scene files under scenes/.

Entities have a kind that defines what they are in the world:

  • 2D — rectangles, sprites, labels
  • 3D — cube, sphere, cylinder, capsule, model (.obj)
  • Lights — directional, point, spot, ambient
  • Camera — frames what Play and export show
  • UI — panels, buttons, and related widgets on the 1280×720 canvas
  • Emitter / empty — particles and empty transform roots

Prefabs (.prefab) store an entity subtree you can instance into any scene. In 3D mode, entities have Z and Depth (distance into the screen). Play simulates full X/Y/Z rigid bodies with Jolt.

Scripting

Game logic is written in Nexa. Put .nxa files in scripts/ and assign them on entities (Script field). On Play or Build, each script compiles to a DLL under bin/. 

#include <eyescire/script>

fn script_init() {
}

fn script_update() {
    let me: int = eng_self();
    /* move, read input, etc. */
}

/* optional */
fn script_draw() {
}
  • script_init — once when Play starts
  • script_update — every frame, per entity that uses the script (eng_self())
  • script_draw — optional custom drawing during Play

Build with Ctrl+B (incremental) or Ctrl+Shift+B (rebuild). The same DLLs ship in an exported game.

2D & 3D

Scenes can render in 2D or 3D (scene setting when nothing is selected). 2D is the layout view; 3D uses the engine renderer (OpenGL 3.3 by default, optional Vulkan 1.4 or OpenGL 1.1).

  • 2D / UI — world sprites and a separate UI canvas (1280×720)
  • 3D — primitives, models, lights, fog / environment; Play uses the main camera
  • Players — 2D exports use the 2D player; 3D exports use EyescirePlayer3D

Navigation in the 3D view uses familiar editor controls (fly, orbit, frame selection). Switch back to 2D layout when you need precise placement on the 2D plane.

Physics

Rigid-body simulation is backend-split by scene mode:

  • 2D — Box2D on X/Y (screen +Y is down)
  • 3D (RENDER 3D) — Jolt Physics in world X/Y/Z (physics +Y is up; scene +Y down maps accordingly)

Gravity and pixels-per-meter are scene settings. Bodies are configured on entities (kind, hitbox, density, friction, etc.); Play calls phys_begin / phys_step / phys_end each session. Scripts use the same phys_* / ent_* APIs; forces and velocities route to the active backend. In 3D, use ent_set_velocity3 / ent_velocity_z (and the *3 force/impulse helpers) when you need the Z axis.

Exporting

Ctrl+E (or Project → Export) writes a runnable build under dist/<ProjectName>/: player executable, engine.dll, project data, compiled scripts, and assets.

  • 2D projects — 2D player + engine runtime
  • 3D projects — 3D player + engine runtime
  • Content protection — optional encryption of shipped content (Settings)

macOS and Linux export targets are not available yet.

Script API

Scripts include <eyescire/script>, which pulls in the engine API (engine/api.nxa and related modules). Grouped overview — not a full symbol list:

AreaUse for
EntitiesTransform, color, visibility, parenting, find / overlap
3DZ, depth, models
InputKeys, mouse, VK_* constants
Timeeng_dt_seconds and frame timing
PhysicsForces, velocity, body setup, gravity / PPM
AudioMusic, SFX, positional sound
UICanvas widgets and button dispatch
Published propsDesigner-facing values on entities

Prefer these APIs over calling host C directly. For the full surface, see engine/api.nxa in the source tree.
